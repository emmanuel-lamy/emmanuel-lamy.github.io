01 — Contexte
Pourquoi ce projet ?

À mon arrivée à l'IRD, la gestion des actifs informatiques (plus de 8 000 équipements) reposait entièrement sur des fichiers Excel et CSV maintenus manuellement. J'ai identifié des risques opérationnels concrets et pris l'initiative de concevoir une solution industrielle pérenne.

⚠️
Risque de corruption des données
Accès simultanés de plusieurs techniciens sur les fichiers CSV sans contrôle de cohérence ni transactions.
🔍
Absence de traçabilité
Aucun historique des opérations de mise au rebut, d'affectation ou de modification du matériel.
🔄
Synchronisation iTop impossible
La CMDB institutionnelle iTop ne pouvait pas être alimentée automatiquement depuis les fichiers Excel.
🔓
Données sensibles sans contrôle
Numéros de série, localisations et responsables stockés sans chiffrement ni contrôle d'accès.

03 — Sécurité
Conformité ANSSI & RGPD

L'ensemble de l'infrastructure a été sécurisé selon les recommandations ANSSI (moindre privilège, défense en profondeur, cloisonnement). Chaque risque identifié a fait l'objet d'une mesure de réduction documentée.

🐳
Hardening conteneurs
  • no-new-privileges:true sur tous les services
  • read_only: true — injection web shell impossible
  • Utilisateurs non-root dédiés
  • Healthchecks automatisés
  • Limitation ressources (deploy.resources)
🌐
Cloisonnement réseau
  • 2 réseaux Docker isolés (DMZ / données)
  • PostgreSQL sans aucun port exposé
  • Nginx seul point d'entrée
  • NAT/PAT : 3 ports seulement (80, 443, 2222)
  • ird_app seul service inter-zones
🔑
Gestion des secrets
  • Tous les secrets externalisés (.env)
  • chmod 600, propriétaire root
  • Exclu du contrôle de version (.gitignore)
  • Injection dynamique au démarrage
  • Aucun secret en dur dans le code
📋
Traçabilité & Audit
  • Table audit_log SQL complète
  • Identité, IP, action, horodatage
  • Non modifiable via l'interface
  • Conforme RGPD (traçabilité accès)
  • Alerting SMTP Grafana automatique
🛡️
Anti-injection SQL
  • ORM SQLAlchemy paramétré
  • Aucune requête SQL concaténée
  • Validation des entrées côté application
  • Principe du moindre privilège DB
♻️
Maintien en sécurité
  • MAJ système Debian mensuelle
  • docker pull + test recette mensuel
  • Rotation secrets trimestrielle
  • docker system prune mensuel
  • SSL/TLS planifié (P1)

Difficultés & solutions
